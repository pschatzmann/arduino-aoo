Detailed Description

AOOReceiver that processes UDP messages in a separate FreeRTOS task.

On ESP32's dual-core architecture this eliminates packet loss by running message reception on one core while audio decoding/output runs on the other.

AOOReceiver itself has no concurrency and stays lock-free; all synchronization needed for that split lives here, since this is the only class where two threads actually touch shared state:

  • mutex guards each source's encoded buffer (written by the receive task, read by the audio-pulling thread).
  • sources_mutex (recursive, since AOOReceiver's sources-touching methods call into each other, e.g. onStart() calls setAudioInfo()) guards the sources list and mixer: the receive task mutates them via processMessages() (new/stopped streams) while the audio-pulling thread reads them in readBytes()/available() and mutates them in postProcessing() (stale/poor-quality source removal). Every override below that touches sources/mixer takes this lock itself, so it stays correct even if called through a base AOOReceiver&/AOOReceiver*.
