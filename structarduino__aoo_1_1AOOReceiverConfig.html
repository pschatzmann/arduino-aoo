Member Data Documentation

◆ adaptive_resampling

bool adaptive_resampling = true

Enable adaptive resampling to compensate for source/sink clock drift: the playback rate is adjusted so that the buffer stays half full

◆ buffer_depth

int buffer_depth = 10

Number of encoded segments to buffer per source. Data is only provided once the buffer is half full, giving time for packet recovery. The priming delay = (buffer_depth / 2) * (block_size / sample_rate). With the default of 10 and typical 10ms blocks: 5 * 10ms = 50ms delay, which is enough for WiFi resend round-trips (10-30ms). Increase to 20 for lossy networks or small block sizes (<5ms). Memory per source: buffer_depth * encoded_segment_size (e.g. 10 * ~100 bytes for Opus, 10 * ~960 bytes for PCM mono).

◆ max_resample_percent

float max_resample_percent = 0.5f

Adaptive resampling: maximum deviation from the nominal sample rate in percent (clock drift is usually far below 0.1%)

◆ min_quality_percent

float min_quality_percent = 80.0f

Only send resend requests when the recent quality (last 100 blocks) is above this threshold: below it resends are suppressed to avoid making congestion worse. Requests for packets the reader has already passed are discarded.

◆ min_source_quality

float min_source_quality = 50.0f

Remove sources whose recent quality (last 100 blocks) is below this percentage. At 50%: a source losing more than half its packets is dropped from the mixer.

◆ no_data_warning_ms

int no_data_warning_ms = 1000

Log a warning if a source sends no audio data for this many ms after its /start message: the data packets are probably bigger than the network MTU (fragmented packets are dropped silently); 0 = disabled

◆ output_follows_source

bool output_follows_source = false

The output format (sample rate, channels) is defined by this config. Set to true to use the format of the first source instead.

◆ recovery_max_requests

int recovery_max_requests = 1

Maximum resend attempts per missing packet. Keep at 1 to avoid flooding the network — the min_quality_percent gate already prevents resends during bad periods.

◆ recovery_wait_ms

int recovery_wait_ms = 10

Wait time in ms before requesting a resend for a missing packet (once a later packet has arrived): it gives reordered packets time to arrive. The resent packet must arrive before the read position reaches the gap, which is about (buffer_depth / 2) blocks behind the newest packet: e.g. 5 * 5.3 ms = 27 ms for 256 samples at 48 kHz, or 5 * 20 ms = 100 ms for 20 ms Opus frames. So the wait plus the round trip time must be clearly below that delay.
